## Tracking rule

Use existing cards as outcome parents. Pull a requirement or narrow defect into a small implementation/acceptance unit only when it is next; prefer native Trello checklist items over duplicate cards. Split software implementation, packaged delivery, human listening and hardware criteria so a partial pass cannot masquerade as complete. Reconcile already accepted evidence instead of rerunning it. Close a parent only when its full retained criteria are satisfied; card count alone is not beta progress.

Optional fingerprint identity, AI playlists/crates, advanced Automix, vendor parity and custom themes remain Later. Metadata/artwork, key reliability and essential usability lead Next after core stability. Do not turn660historical reference requirements into660new beta tasks.
