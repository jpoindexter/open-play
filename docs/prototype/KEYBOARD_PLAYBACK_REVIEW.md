18 October 2026, source after private checkpoint `6abf0e2`. Native 0.1.15 stays unchanged and ready for the human controller test. This source change is **not packaged into that build**.

W/S now toggle Play/Pause once per fresh keydown; auto-repeat cannot stop/restart a deck. Q/A invoke existing Reverse and F5/F10 invoke existing Keylock, also ignoring repeat. T/Y and G/H hold temporary down/up bends on the left and right decks. All new playback bindings obey Playback Keys Use Shift and avoid text fields, open dialogs and Command/Control/Option combinations on press. Keyup still releases after focus moves to an input; window blur and hidden-document notification release keyboard holds.

Keyboard and MIDI jog input share one existing bend controller. Keyboard fraction is an independently chosen ±4%; combined input stays within the existing ±8% cap. Opposing keys cancel, releasing one restores the remaining input, and MIDI's 150ms idle return preserves held keyboard input. Nominal deck rate stays owned by tempo/Sync. These numerical responses are Open Play policy; the official shortcut table establishes key names, not a measured Serato taper. Reference: [Serato keyboard shortcuts](https://support.serato.com/hc/en-us/articles/233087008-Keyboard-Shortcuts).

Later attempts wrongly compared Float32 AudioParam values with exact decimals, and one synthetic packet used form defaults after Add Mapping rerendered the fields (actual log CC ch1#1 versus intended ch2#9). Corrected the harness to use normal controls, reset actual visible message fields and consistently apply the already-used 1e-7 metadata comparison. No production change or 0.5Hz/RMS audio-gate relaxation was made to turn these attempts green. Complete failed reports/recordings remain; they are not relabeled as passing runs.
