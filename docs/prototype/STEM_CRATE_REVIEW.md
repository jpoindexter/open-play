## Behavior and reference

[Serato’s preparation guide](https://support.serato.com/hc/en-us/articles/5700969287183-Preparing-tracks-for-use-with-Stems) describes crate-based preparation without loading a deck, pending/ready indicators and Command/Ctrl+Delete removal that retains the library track. The prototype previously filtered only decoded in-memory buffers, losing crate contents on reload and keeping entries visible after files were cleared.

Explicit inStemCrate metadata now survives with each track. Crate drop and manual Prepare selected add a member; on-demand/on-load preparation of a new nonmember does not force membership. Legacy saved job associations migrate into membership when no explicit Boolean exists. Loaded audio buffers are separate from saved membership/cache. Pending/failure entries remain visible for retry. The sidebar is named Stems.

A filled ready marker is shown only after the service confirms the matching completed job, duration compatibility and four canonical source names. Checking, preparing, unavailable and offline states stay distinguishable with shapes and accessible labels, not color alone. Status updates preserve row focus; the actual service status read validates the four export hashes and reports changed/incomplete caches failed. No inference or decoding is needed to verify readiness after reload. A ready cache is not a model-quality or universal-compatibility assertion.

Command/Ctrl+Delete or Backspace operates only in the Stems library region, ignores key repeat and retains the library entry/original File. It cancels an unfinished preparation and moves known generated job folders to native Trash; an already committing activation finishes before removal. Decoded sources/playing voices are retained. A missing saved job removes membership with an explicit unavailable-job message rather than claiming unknown files were moved. Other failures retain membership for retry. Existing preparation-dialog Clear also removes crate membership on confirmed success.
